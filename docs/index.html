A coding agent that runs on your Mac. No API key.

Written in C for a local model. No cloud account. On macOS, the commands it runs are sandboxed.

git clone https://github.com/megasoft1978/flywheel cd flywheel && make ./flywheel setup # asks first ./flywheel

One real run, 56 s, uncut. A script answered "Yes" to every approval. Recorded with an earlier build, before the sandbox and image input. About the recording

Apple Silicon Mac with clang and libcurl. setup needs Homebrew and aria2c; model and drafter take about 19 GB. Tested on an M5 Max with 64 GB; smaller Macs are untested.

A loop built for a local model's mistakes

File edits skip the sandbox but are confined to the project. The interactive UI asks before anything outside a short read-only list, and before the check, unless you chose "always allow": a remembered command is not asked again, even if the model has since changed the files it runs. Only TypeScript, Python, Go and Rust projects (the last two experimental) get a check gate; others finish without one. A passing check means the code type-checks or compiles, not that it is correct.

What a model's command can touch on macOS

Read and write

  • Your projectexcept git hooks, git config, .envrc and other protected files
  • A private temp directorynot /tmp

Readable by the model

  • A .env in the projectand other secrets there
  • Toolchains and dependenciesa fixed list under your home, plus some git files
  • Everything outside your homethat you can read yourself

Blocked

  • Writing anywhere elseexcept, in a linked git worktree, parts of the main repository's git data
  • The rest of your home directory
  • Credential storesa fixed list: ~/.ssh, ~/.aws, keychains, common browser profiles and others
  • The networkunless you approve one command in the interactive UI; it can then reach any address

Start flywheel in a project directory: started in your home directory, commands can read and write nearly all of it. Every rule and exception

Show it a screenshot

  • Drag an image onto the terminal, or type its path: ./shot.png, not a bare name
  • Give an image URL (not in the static Linux build)
  • /paste a picture from the clipboard (local macOS session)

Only what you type or paste is searched for images. Naming a file attaches it, even outside the project. The engine must serve the model with vision; flywheel setup starts it that way. Details

What you get

Local, no API key

Talks to a model server on your Mac. Sends no key.

Loop breaker

Prunes repeated turns, adds a correction, briefly raises temperature.

Tool-call repair

Recovers shell commands from JSON with raw control characters. Truncated ones never run.

Careful edits

Unique-match replacements, confined to the project.

Live terminal UI

Type while it works. Esc interrupts. Output collapses.

Small enough to read

About 11k lines of C plus cJSON. Only libcurl on macOS.

Safety, before you run it

  • No sandbox on Linux.Approved commands can write anywhere you can and use the network.
  • A project .env is readable by the model.So are other secrets in the places it may read.
  • One-shot approves commands automatically.One-shot means a prompt argument, -f or piped input. So does bench. Network access is the exception.
  • Use a VM for untrusted repositories and tasks.Files in the project can change, including build scripts you may run later.

--unsafe turns off the sandbox, on macOS too, and environment filtering. Where there is no sandbox, one-shot and bench refuse to run without it. Read the full safety page

Limits

  • No API key support, so hosted services that require one do not work
  • The Linux build has no HTTPS and no sandbox
  • No context compaction
  • Images from typed or pasted input only; no audio or video
  • Go and Rust checks are experimental
  • Tuned on a private test suite
